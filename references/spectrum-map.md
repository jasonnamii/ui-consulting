# 4단계 스펙트럼 맵핑 규칙

ux-advisor의 핵심 엔진. 사용자 질문을 4단계로 분기할 때의 판정·생성 규칙.

---

## 축 정의

**단일 축**: 관행 이탈도(시대감각 + 리스크 + 임팩트의 복합)

| 단계 | 이름 | 한 줄 정체성 | 대표 감정 |
|------|------|------------|---------|
| 🟦 | 보수 (옛날 스타일) | 검증된 과거 관행. 학습비용 0 | 안전감 |
| 🟩 | 일반 (요즘 스타일) | 현재 시장 주류. Jakob's Law 준수 | 친숙함 |
| 🟨 | 진보 (조금 도전) | 주류+변주 1~2개. 멘탈모델 유지 | 차별감 |
| 🟥 | 혁명 (완전 와우) | 멘탈모델 자체 재정의. First Principles | 경외·불안 |

---

## 생성 규칙 (각 단계별)

### 🟦 보수
- **기준**: 10년+ 검증된 패턴. 업계 레거시.
- **사례 풀**: Windows 95 튜토리얼·eBay 2005·카드입력 5스텝 결제·햄버거 메뉴·시간순 타임라인
- **이론 기반**: Jakob's Law(최대한 관례), Consistency, Miller's Law 엄격 적용
- **위험**: 차별화 불가. 레드오션 탈출 불가.
- **적합**: 관공서·금융 규제·노년층 타겟·미션크리티컬

### 🟩 일반
- **기준**: 현재 2~5년 주류. 경쟁사 동급.
- **사례 풀**: Instagram 가입 3스텝·Apple Pay 원탭·Material Bottom Nav·Coupang 로켓배송
- **이론 기반**: Jakob's Law + 기본 휴리스틱 10개 준수
- **위험**: 튀지 않음. "무난하다"
- **적합**: 대중 서비스·B2C 범용·학습비용 최소화 우선

### 🟨 진보
- **기준**: 주류+변주 1~2개. 멘탈모델은 유지하되 신선함 주입.
- **사례 풀**: Slack Progressive·Duolingo 대화형 온보딩·Toss PIN·Linear 키보드·Notion 블록
- **이론 기반**: Peak-End·Goal Gradient·Von Restorff (차별화 원리)
- **위험**: 구현 난이도 상승. 일부 사용자 혼란.
- **적합**: 스타트업 MVP+·브랜드 차별화 필요·Power User 타겟

### 🟥 혁명
- **기준**: 카테고리 문법 자체 재정의. First Principles로 재설계.
- **사례 풀**: Amazon 1-Click·ChatGPT·TikTok FYP·Amazon Go·Figma 실시간 협업·BeReal·Humane Pin
- **이론 기반**: Tesler's Law 역이용(복잡성을 어디로 보낼지)·Trigger Model 재설계
- **위험**: 학습곡선 급상승. 실패 시 전면 이탈. 시대 선행.
- **적합**: 카테고리 킬러 목표·투자 유치 서사·Vision 급 프로덕트

## 생성 포맷 (고정)

각 단계 답변은 **반드시 4요소** 포함:

```
🟦 보수 (옛날 스타일)
**원리**: 한 줄 정의
**이론**: NN 휴리스틱 / 법칙 / 모델 1~2개 인용
**사례**: 실제 서비스 2~3개
**비유**: 기억에 박히는 비유 1개
```

---

## 가장자리 케이스

### 질문이 "보수"가 이미 정답인 경우 (예: 정부 공공앱)
- 🟦에 무게를 두되 🟥은 **"혁명이 역효과"** 경고로 답변
- 전 단계 제공 원칙 유지 (사용자 판단 존중)

### 질문이 혁명을 전제로 하는 경우 (예: "와우한 UX 만들자")
- 🟦🟩은 짧게(반면교사로), 🟨🟥에 무게

### 혁명 사례가 없는 신영역
- 🟥은 **인접 카테고리에서 유사 혁명 사례 차용** + "미개척 기회" 플래그
- 예: "AI 노인돌봄" 혁명 사례 없음 → Calm(명상)·Noom(대화코칭) 유사 구조 차용

## 하이브리드 팁 (답변 하단 추가)

```
💡 하이브리드 팁
- 1차 출시: 🟩 (시장 진입 속도)
- 2차 업데이트: 🟨 (차별화 주입)
- 3차 피벗: 🟥 (카테고리 재정의 도박)
또는
- 핵심 기능은 🟩 / 시그니처 기능 1개만 🟥
```

## 선택 가이드 판정 기준 (필요시 제공)

| 상황 | 추천 | 이유 |
|------|------|------|
| 규제·안전 중요 | 🟦 or 🟩 | 혁명은 규제 리스크 |
| 타겟=노년·비숙련 | 🟩 | 학습비용 최소 |
| 타겟=얼리어답터·Gen Z | 🟨 or 🟥 | 차별화 민감 |
| 리소스 제약 | 🟩 | 구현·CS 비용 |
| 투자 라운드 앞둠 | 🟥 | 비전 서사 |
| 기존 유저 베이스 큼 | 🟨 | 급격한 변화 위험 |
| MVP 빠른 검증 | 🟩 | 시장 반응부터 |
